# 家のルーター

ルーターには API が無いので、設定はここに書いて持つ(IaC にはできない)。**ルーターの設定を変えたら、ここも直す。**

値は 2026-10-07 に管理画面(クイック設定Web)とノードで読んだもの。

## 機器

| 項目 | 値 |
| --- | --- |
| 機種 | au ひかりのホームゲートウェイ **BL1500HM**(KDDI) |
| 管理画面 | `http://10.0.0.1/`(クイック設定Web。ログインが要る) |
| 回線 | au ひかり(接続はホームゲートウェイが持つ。IPv6 はネイティブで RA が来る) |
| 外向きの IPv4 | 固定ではない。cloudflare-ddns が `doany.io` と `nb.origin.doany.io` を追従させる(apps/cloudflare-ddns/) |
| IPv6 | プレフィックス `240f:6d:842b:1::/64`(RA で配られる。**変わりうる**ので、どこにも固定で書かない) |
| IPv6 の受信 | 「IPv6ホスト公開」の既定は**「遮断」**で、**ノードだけをエントリで公開**(MAC `e6:2c:1b:1a:a0:39`、IPv6 すべて、ポート any。下の「IPv6 はノードだけを公開する」)。IPv6 パケットフィルターは有効で、WAN 側の規則は 0 件 |

## 外からの転送

**DMZ(すべての受信)をノード `10.0.0.2` に向けている**(「DMZホスト設定」。ポートマッピングは 0 件)。個別のポート転送ではないので、ノードで受けているものは全部外に出る。
DMZ の向け先を変えると、下の全部と AdGuard の split-horizon が一斉に外れる(decisions.md「LoadBalancer をどう置き換えるか」)。

ノードで受けているもの(hostPort。増やすと、それも外に出る):

| ポート | 何 | 外から要るか |
| --- | --- | --- |
| 80 / 443 TCP | Gateway(全部の Web) | 要る |
| 53 UDP・TCP | AdGuard Home(平文の DNS) | 要らない。Pod の手前で止めている(下の「53 番は外に出さない」) |
| 853 TCP | AdGuard Home(DoT) | 要る |
| 8443 UDP・TCP | LiveKit(Matrix の通話。apps/matrix/README.md) | 要る |
| 51820 UDP | NetBird の routing peer(WireGuard) | 要る |
| 3129 TCP | 3proxy の TLS 口(apps/3proxy/) | 外から使うなら要る |
| 6443 TCP | Kubernetes の API(`ks.doany.io:6443`。recovery/README.md) | 要る(認証つき) |

**ノード自身が受けるもの(Talos の API 50000・trustd 50001・etcd・kubelet 10250・Cilium の 4240 / 4244 / 9963 / 9964 など)は、
ノードの受信の防火壁で外から止めている**(`bootstrap/talos.sops.yaml` の `NetworkDefaultActionConfig` と `NetworkRuleConfig`。
2026-10-31 に足すまでは DMZ と IPv6 ホスト公開で外から全部届いていた)。既定は捨て、外から通すのは上の表のポートだけ
(TCP 80・443・853・3129・6443・8443、UDP 8443・51820)、内側のアドレス(LAN と Pod・Service の 10/8・NetBird の 100.64/10・
fc00::/7・fe80::/10)からは全部。効くのはノード宛てだけで、hostPort(53・853・8443・3129・51820)は Cilium が Pod へ転送するので
通らない(なので 53 番は下の Cilium のポリシーで止めている)。表にポートを足すときは `public-tcp` / `public-udp` にも足す。
家の LAN の IPv6 の GUA はプライベートに入れていないので、LAN からノードの管理の口へは IPv4 で繋ぐ。

## 53 番は外に出さない

DMZ では 53 番も外に届くが、AdGuard Home の Pod の手前で、プライベートのアドレス(家の LAN・NetBird)以外からの 53 番を
Cilium のポリシーで捨てている(apps/adguardhome/network-policy.yaml)。外から使う DoT(853)と DoH は絞らない。
以前は開けていたが、2026-10-31 に、送信元を偽装した増幅攻撃の踏み台として 1 日 90 万件使われていたので閉じた。
AdGuard の `allowed_clients` で絞らないのは、DoT・DoH にも効いて外の端末が使えなくなるため。

## IPv6 はノードだけを公開する

「IPv6ホスト公開設定」の既定を「遮断」にし、ノード `main` だけをエントリで公開している(既定の「公開」だと LAN の全端末に外から IPv6 で直接届く)。

- **エントリは MAC アドレスで指す**(bond0 の `e6:2c:1b:1a:a0:39`。`talosctl -n 10.0.0.2 get links bond0` で見る。ルーターの「接続端末 情報画面」にも同じ値が出る)。IPv6 アドレスで指すと、RA のプレフィックスが変わったときに外れる
- **この MAC はノードの設定で固定している**(`bootstrap/talos.sops.yaml` の `BondConfig` の `hardwareAddr`)。固定しないと bond は先頭のメンバーの MAC を引き継ぎ、
  再起動で変わってエントリが外れる。NIC を替えても Z440 に移しても、この値は変わらない
- **公開する AAAA は静的な `::2`。** cloudflare-ddns の `local.iface.stable:bond0` は一時アドレス以外から選ぶので、SLAAC のアドレスがあると
  そちらを書いてしまう。`bond0` は `autoconf=0`(bootstrap/talos.sops.yaml)で SLAAC を付けない
- 公開の中身は DMZ と同じ(IPv6 すべて・ポート any)。ノードで受けているものは IPv6 でも外に出る(ノードの管理の口は IPv4 と同じくノードの防火壁が止める。上の「外からの転送」)
- `fj` / `nb` / `m` / `ks` / `lk` などの AAAA はノード(`240f:6d:842b:1::2`)を指すので、**このエントリを消すと IPv6 の利用者から直接つなぐアプリが見えなくなる**
- 確かめ方: 別の回線の IPv6 から名前で開く(アドレス直打ちは SNI が無く Gateway が切る)。J:COM 側の PC から
  `curl -6 -so /dev/null -w "%{http_code} %{remote_ip}\n" https://fj.doany.io/` で `200 240f:6d:842b:1::2`
- ノードの設定で bond0 の MAC を変えたら、エントリも直す

## ヘアピン NAT(NAT ループバック)

**有効にしておくこと。** 家の中の端末も、LiveKit や NetBird が STUN で調べた外の IP に向けて送る。
無効だと家の中からだけ通話がつながらない(apps/matrix/README.md「ルーターの転送」)。
Web も、AdGuard を使う端末(端末側で指定したもの・NetBird の端末)は split-horizon で `10.0.0.2` を引くのでヘアピンに頼らないが、ルーターの DNS のままの端末は外の IP を引くので、**Web もヘアピン頼み**。

## 作り直す・機種を替えるとき

1. LAN を `10.0.0.0/24`、ルーターを `10.0.0.1` にする。DHCP の範囲は `10.0.0.10` から(ノードの `.2` に被らないこと)
2. ノードを `10.0.0.2` にする
3. DMZ を `10.0.0.2` に向ける
4. ヘアピン NAT を有効にする
5. IPv6 ホスト公開の既定を「遮断」にし、ノードの MAC だけをエントリで公開する(上の「IPv6 はノードだけを公開する」)
6. 外から確かめる: `https://doany.io`、Element の通話、NetBird の接続

## 10.10 側(JCOM)のルーター

`10.10.0.0/24` は別の回線(J:COM)。分かっていること(2026-10-11):

| | |
| --- | --- |
| 機種 | HUMAX **HGJ310V4**(ケーブルモデム一体。Plume / OpenSync で管理される機種) |
| 設定 | Web の画面(`http://10.10.0.1`)は見るだけ。IP の予約やポート転送は **J:COM のアプリ**から(「設定 → ネットワーク → IP 予約」で端末を選び、その中で転送を足す)。静的ルートの設定は無い |
| IP | **固定 IP の契約**(IPv4 `61.21.173.41`、IPv6 プレフィックス `2405:1201:5201:3a00::/64`)。ルーターの画面の「WAN タイプ: 動的 IP」は契約に関係なくこう出る |
| IPv6 | **外からの接続を何も止めない。** au 側の `main` から、この LAN の PC の IPv6 に TCP でつながった。守っているのは各機器のファイアウォールだけ |
| Guard | アプリの「Remote Access Protection」は無効にしておく(有効だと、転送したポートも許可するまで止まる) |

**アプリで 10.10.0.2(OD00)を予約し、TCP 80 / 443 をそこへ転送している。** `main` が落ちたときの入口の
[mado](../mado/)(`md.doany.io`)のため。
